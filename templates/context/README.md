# .context/ —— 知識層

**這個專案做了什麼、為什麼、現在到哪。** 規範在 `.claude/rules/`，
專案是什麼在 `CLAUDE.md`，這裡是第三層。

| 檔案 | 放什麼 | 怎麼載入 |
|---|---|---|
| `current-focus.md` | 現在在做什麼、下一步、卡點 | 常駐區由 hook 注入 |
| `background.md` | 研究背景、風險、技術備忘 | 按需 |
| `decisions.md` | 決策史。**只增不改** | 按需 |
| `conventions.md` | repo 慣例、目錄意義、命名 | 按需 |
| `log/` | 逐次紀錄 | 進 `.gitignore` |
| `archive/` | 重整前的凍結原件，**不得編輯** | 不載入 |

## 三個容易搞混的界線

**規範 vs 知識**：換一個專案還成立 → `.claude/rules/`；只有這個專案成立
→ 這裡。

**決策 vs 現況**：`decisions.md` 記「當時決定了什麼、為什麼」，只增不改；
`current-focus.md` 記「現在是什麼狀態」，隨時改寫。同一件事在兩邊各有一份
是正常的，不要合併 —— 一個是歷史，一個是約束。

**歷史紀錄裡的路徑會過期**：`decisions.md` 提到的檔案路徑是當時的路徑。
目錄重整之後不要照著去讀檔。在檔頭寫一句警語，比逐條改路徑好 ——
改了會讓紀錄失真。
